Skill（AI 技能）

你正在用的这份「concept-learner」就是一个技能——这份资料顺便把技能本身讲清楚。

🎯学习目标

1

能解释 Skill 是什么、它解决什么问题，以及它和普通提示词（Prompt）的区别。

2

能拆出一个技能包的组成（元信息 / 步骤正文 / 附带资产），讲清它被触发的机制。

3

能区分 Skill、Tool、Agent、MCP 四者的分工，并说出使用技能的注意事项。

❓带着 3 个核心问题去学

  • 问题一：AI 助手明明已经很会聊天，为什么还需要「技能」？直接说清楚要求不就行了吗？
  • 问题二：一个技能文件（比如 SKILL.md）里通常写了什么？助手靠什么判断「该不该调用它」？
  • 问题三：Skill、Tool、Agent、MCP 这几个词天天一起出现，它们各自负责哪一环？

💡个人化解释：技能 = 给 AI 的「岗位说明书 + 标准作业手册」

把 AI 助手想成一个能力很强、但每次上班都「失忆」的新员工。它的问题在于：哪怕昨天你手把手教过它一套流程，今天它又全忘了，你得从头再教一遍。

Skill（技能）就是解决这个问题的文件：把你教它的那套「怎么做」写成一份标准作业手册（通常是一个 SKILL.md 文本文件），放进指定的文件夹。以后只要任务对口，助手会自己翻开这本手册、照章办事——流程再复杂也不会走样，换台设备、换个人也能复用。

一句话记忆：Skill 把「一次讲清楚」升级成「永久可复用」。它的价值在于沉淀流程，让高质量的做事方法可以打包、分享、随时调用。

一个就近的例子：concept-learner 就是你现在这个学习工具里装的一个技能。它的手册里写着「生成学习资料必须包含：学习目标、3 个核心问题、通俗解释、机制拆解、应用场景、辨析、3 道自测题、可核查来源」——你连说了三次「帮我学一个概念」，三次产出的结构都一模一样，靠的就是这本手册。

⚙️核心机制与组成拆解

① 一个技能包长什么样

以主流的 SKILL.md 形式为例，技能是「一个文件夹」，通常包含：

📁 my-skill/
  ├─ SKILL.md ← 核心：元信息 + 操作步骤
  ├─ assets/ 可选：参考文档、模板、示例
  └─ scripts/ 可选：配套脚本或工具
📇 元信息（frontmatter）
文件开头的 name 与 description。description 写清「什么场景下用这个技能」，它是助手判断要不要调用的触发开关。
📋 步骤正文
按顺序写清完成任务的流程、质量标准、注意事项，相当于「标准作业手册」本体。可长可短，结构化最利于执行。
📎 附带资产
模板文件、参考示例、脚本、清单等。让技能携带「素材」，执行时不必现找。

② 技能的运行机制：五个环节

1
提出请求
你发出任务，例如「帮我学一下 XX 概念」。
2
匹配触发
助手对照已安装技能各自的 description，判断哪个技能与任务对口。写得好不好，直接决定触发准不准。
3
加载手册
把对应 SKILL.md 的内容读进上下文，助手此刻「知道该怎么做了」。
4
照章执行
按步骤工作；期间可调用工具（搜索、读写文件等），必要时参考附带资产。
5
交付结果
按手册定义的质量标准输出成品，流程结束。

③ 为什么说它解决了「提示词工程」的痛点

早期让 AI 按固定流程做事，要把整段指令反复粘贴进每一条对话（提示词工程），又长又易错又难维护。技能把这段指令外置成文件、按需加载：对话更干净、流程更稳定、经验可积累、团队可共享，还常配有安全检查机制。

🚀一个具体应用场景：给备考助手装一个「时政卡」技能

设想你在积累申论与专业课共用的时政素材。每次都口述要求，AI 产出的格式会飘忽不定。于是你写一个技能 shizheng-card：

在 description 里写：「当用户要求整理时政热点 / 生成申论素材卡时使用。」
在步骤正文里规定：「每张卡片须含 ①事件概述（100 字）②政策/理论背景 ③社会意义 ④可用论点与适用主题 ⑤信息来源。检索后须核实来源再输出。」

之后你只需说「整理今天的时政」，助手就会自动套用这套规范产出卡片。收益有三点：

  • 稳定：格式永远统一，直接并入你的笔记体系，无需二次整理。
  • 可靠：手册里写死了「核实来源」这类关键步骤，不依赖 AI 当天的心情。
  • 积累：技能跟着你的资料夹走，换电脑、升级助手都不丢。

⚠️容易混淆的地方 & 使用边界

概念关键区别
Skill vs PromptPrompt 是一次性写在请求里的话；Skill 是持久化的复用单元，含结构化流程与附带资产，按需加载。
Skill vs ToolTool（工具）是可调用的函数接口，一次调用、返回结果（如「搜索」「发邮件」）；Skill 是「怎么完成任务」的说明书，内部可编排多次工具调用。
Skill vs AgentAgent 是能自主规划行动的主体；Skill 是它携带的专业能力包。一个 Agent 可同时挂载多个技能，按任务挑选使用。
Skill vs MCPMCP 是给「工具/数据」定统一接口协议（让不同系统能互通）；Skill 装的是操作流程与知识。二者互补：MCP 提供能力通道，技能指挥怎么用。

使用边界：技能常见误区

  • 技能改变不了模型的基础能力：它优化「怎么做」，无法凭空造出模型本就不会的推理。期望要合理。
  • 触发依赖描述质量：description 写得含糊，助手可能漏触发或误触发——写清楚「什么请求该用它」很关键。
  • 有安全与质量成本：技能可能携带脚本、指令外部来源的内容，安装前应做安全审查；效果参差，需实际测试。
  • 占用上下文：技能被加载后其内容进入上下文，技能过多或过大会挤占窗口、推高成本——只装常用且精简的技能。
判断口诀：「凡是希望你每次都用同一套高质量流程做的事，都值得沉淀成一个技能」——一次写清，长期复用。

📝3 道自测题（点选项查看结果）

第 1 题Skill（技能）在 AI 助手中主要解决什么问题？
A. 让模型的推理能力变强、知识变多
B. 把「怎么做某类任务」的方法沉淀为可复用文件，让助手按需加载、稳定执行
C. 替代用户输入，自动完成所有对话
D. 让模型能离线运行
解析技能封装的是「流程与知识」而非「模型能力」——模型的基础能力并不因技能而改变，价值在复用与稳定。
第 2 题技能文件（SKILL.md）里的 description 字段，最主要的作用是？
A. 给文件取一个好看的名字，方便人类阅读
B. 记录技能的版本号与作者信息
C. 帮助助手判断「什么样的请求应该触发这个技能」
D. 对技能内容进行加密保护
解析description 相当于技能的「门牌与简介」，是助手做触发匹配的依据；写清楚适用范围能显著提升触发准确率。
第 3 题关于 Skill 与 Tool（工具）的区别，下列说法准确的是？
A. Tool 是可调用的函数接口，一次调用返回结果；Skill 是指导如何完成任务的说明与流程，内部可编排多个工具调用
B. 两者完全相同，只是叫法不同
C. Tool 只能在联网时使用，Skill 只能离线使用
D. Skill 比 Tool 更底层，Skill 是 Tool 的一种
解析工具是「手脚」，一次调用干一件事；技能是「手册」，告诉 AI 用哪些手脚、按什么顺序把整件事干完。技能可以编排工具，方向与 D 相反。
